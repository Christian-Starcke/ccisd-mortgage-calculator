# Clear Creek ISD mortgage calculator

Durable notes for agents. `AGENTS.md` is regenerated by `next dev`; keep project facts here.

## The one thing to internalise

**This district spans two appraisal districts that share nothing.** Harris and
Galveston use different parcel ids, different taxing-unit codes, different
countywide unit sets, and different data delivery. Clear Creek ISD itself is
`027` in Harris and `S16` in Galveston. A county is never optional: it travels
with every parcel id (`ParcelRef`) and every code lookup
(`resolveUnitsFromCodes(county, codes)`). Code that forgets it will silently
price a Galveston house with Harris units, which is wrong by about 60 cents per
$100.

## Do not reverse

- Live lookups plus a manual fallback. **Never auto-select a parcel.**
- Geographic scope is Clear Creek ISD only (`027` / `S16`). Hard-warn any other
  school code. A parcel with two school codes is a split parcel: warn, do not
  model the apportionment.
- Rates and homestead exemptions live in version-controlled TypeScript so a
  change is a reviewable diff with a source URL. **Only** the parcel-to-unit
  mapping lives in Supabase.
- Presets are built by reading codes out of the generated tables
  (`requireUnit(county, code)`), never by restating rates. One copy of each rate.
- Missing rates must not be treated as $0. Surface them and ask
  (`missingRateCodes`).
- **Reinvestment zones levy nothing and must not be billed.** Harris names them
  ("TIRZ 1 CITY OF FRIENDSWOOD"), so they are classified by name. Galveston uses
  bare `T`/`P`/`I`/`E` codes absent from its rate table, so they are classified
  by prefix — an explicitly *unverified* inference the UI discloses. Billing one
  would roughly double-count the city tax.
- A genuinely zero rate (Clear Lake Shores levies no city tax) is not a missing
  rate. Drop it from the bill; do not flag it.
- Both code paths must agree: `resolveTaxingUnits` filters zero-rate base units
  because `resolveUnitsFromCodes` does. Otherwise the same house shows a
  different number of line items depending on how you got there.
- A utility district can only bill a parcel its own county appraises.
  `withUtilityDistrict` enforces this; do not remove it, or a stale Galveston
  MUD selection follows the buyer to a Harris address.
- Seller exemptions do not transfer. Homestead resets on sale.
- Appraised value and listing price stay separate. Warn when they diverge.
- Appraisal cap models **purchase year + 2** (`yearsBeforeCapApplies` default 2).

## Windstorm is a first-class payment line

`src/lib/windstorm.ts`. Not an insurance detail — it is the largest cost
difference inside the district, roughly $200/month between League City and
Webster.

- All of Galveston County is in the TDI-designated catastrophe area.
- Harris County is designated **only** east of Highway 146 **and** inside La
  Porte, Morgan's Point, Pasadena, Seabrook or Shoreacres city limits. Of this
  district's cities only Seabrook (`076`) and Pasadena (`074`) can qualify.
  Everything else on the Harris side — Webster, Nassau Bay, El Lago, Taylor Lake
  Village, Friendswood, Clear Lake City — is outside it.
- Those two cities return `boundary-uncertain`: assume the premium (conservative)
  and ask the user. **Do not invent a longitude cutoff for Highway 146.** The
  centroid is available and it would look precise; the designation follows the
  right-of-way and the city limit together, so a threshold produces confident
  wrong answers.
- Inside the designated area the homeowners policy *excludes* wind, so its rate
  is deliberately **lower** (7.0 vs 10.5 per $1,000). Adding windstorm on top of
  an all-perils rate double-counts the peril and overstates the payment by ~$80
  a month. If you change one rate, reconsider the other.
- Windstorm is escrowed and prepaid like any hazard premium, and it must reach
  `monthly.total`, not just the breakdown line. There is a test for exactly that.

## Where things live

- Engine is pure TypeScript under `src/lib`. UI never computes a payment itself.
- `buildFromState.ts` maps `CalculatorState` → engine inputs. `scenario.ts` is
  the engine entry. `pathRank.ts` picks the best loan + assistance stack.
- UI state, defaults and `STORAGE_KEY` live in `src/lib/defaults.ts`. Persistence
  spreads defaults over stored JSON; bump the key only for incompatible shapes.
- Address search: `GET /api/address?q=`. Parcel:
  `GET /api/property?parcel=<county>:<id>`.
- No third-party runtime dependencies beyond Next and React. Supabase is reached
  over PostgREST with `fetch`. Keep it that way unless there is a real reason.

## Per-county lookup quirks

**Harris** (`hcad.ts`, live at `gis.hctx.net/.../HCAD/Parcels/MapServer/0`)
- Structured address fields, so the house number is an integer match on
  `site_str_num`. Better than a situs blob; do not regress it to `LIKE`.
- **No `taxunits` field and no `exemptions` field.** Codes come from the stored
  footprint, joined on `acct_num`. An account with no stored row is outside the
  district — that is the mechanism behind the out-of-district warning.
- `site_city` is the **postal** city: a Nassau Bay address reads "HOUSTON". Never
  derive the taxing city from it.

**Galveston** (`parcelStore.ts`)
- No query service exists. The stored GCAD drop *is* the lookup, and its rows are
  a dated snapshot the UI must label as such.
- `SITUS` is the property address; the `CITY`/`ZIP` columns are the **owner
  mailing** address and disagree on roughly a third of rows. Never use them.
- `GEOID` repeats across polygon parts (~250 in the footprint), with identical
  attributes. The ingest dedupes; without it Postgres rejects the whole batch.
- No geometry in the drop, so **no flood or USDA point lookup** on this side.
  Report unknown; do not substitute the Harris answer.

## Address parsing

City names are stripped as a **trailing phrase**, never filtered token by token.
Around Clear Lake the city names *are* street names — Clear Lake City Blvd,
League City Pkwy, El Camino Real, Nassau Bay Dr. Token filtering deletes the
street and turns a precise search into a house-number sweep of two counties.
`TRAILING_CITIES` is ordered longest-first so "LEAGUE CITY" is consumed before a
bare "CITY". There are regression tests; keep them.

## Assistance is scoped by administering government

`eligibleLocationIds` is load-bearing, not decoration. City of Houston HAP is
Houston city limits only (`houston-clear-lake`). Harris County DAP covers Harris
County outside Houston and **none** of Galveston. There is deliberately no
Galveston County programme — none could be confirmed, and roughly 44% of the
district is over there, so that gap is documented rather than papered over with a
placeholder. A local-government programme with `eligibleLocationIds: null` is a
bug; a test asserts against it.

## USDA

No part of this district is USDA-eligible — it is continuously built-up suburban
and coastal Houston. The program stays in the catalog so the comparison can say
what is unavailable instead of going quiet, and the lookup stays because it is
cheap and honest. Do not delete either; do not pretend it might apply.

## HOA

Neither appraisal district records HOA. `hoaCertainty`: `unknown` uses the
location-typical midpoint (labeled estimate), `none` is $0, `known` uses
`annualHoaDues`.

## Refreshing data

Annual, each October (rates adopt by Sept 30; HCAD certifies mid-August).
`npm run build:footprint` → `npm run build:harris-units` →
`npm run ingest:parcels`, then re-verify `galvestonTaxUnitCodes.ts` against the
current GCAD PDF by hand. Needs ~1.5 GB of source drops in `data-drop/`; see the
README. `--dry-run` on the ingest parses without writing.
